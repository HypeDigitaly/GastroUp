# src/ — modular page sources

All deployed HTML pages are **assembled at build time** from the partials in this
directory by `scripts/assemble.js` (invoked from `build.js`). The output is the
same single-file, fully-inlined HTML as before — same performance, now with a
maintainable source layout where **every file stays under 500 lines**.

```
src/
├── pages/                  ← one template per deployed page (entry points)
│   ├── index.html
│   ├── obchodni-podminky.html
│   ├── ochrana-osobnich-udaju.html
│   └── 404.html
├── components/             ← reusable, parametrized building blocks
│   ├── analytics.html      ← GA4 + Consent Mode v2 snippet (all pages)
│   ├── cookie-banner.html  ← cookie consent banner HTML+JS (all pages)
│   ├── cal-button.html     ← Cal.com demo <button>  ({{class}}, {{label}})
│   ├── cal-link.html       ← Cal.com demo <a> link  ({{label}})
│   ├── checkout-button.html← FAPI checkout <button> ({{tier}}, {{class}}, {{label}})
│   ├── checkout-cta.html   ← FAPI checkout <a>      ({{tier}}, {{class}}, {{label}})
│   ├── checkout-promo-cta.html ← gold promo CTA with price-strike ({{class}})
│   └── legal/              ← shared by both legal pages
│       ├── head-meta.html  ← icons + fonts + iconify
│       ├── nav.html        ← page header / mobile drawer
│       ├── footer.html     ← footer ({{privacy-current}}, {{terms-current}})
│       └── mobile-menu.html← drawer JS
├── sections/index/         ← landing page sections, in page order
├── styles/                 ← landing page CSS (inlined into <style>)
│   └── legal/              ← legal pages CSS (shared top/bottom + per-page)
└── js/                     ← landing page JS modules (inlined into <script>)
```

## Include syntax

```html
<!-- @include components/cal-button.html class="btn btn-ghost" label="Demo zdarma" -->
```

- Paths are **relative to `src/`**; includes resolve recursively (max depth 10).
- Parameters fill `{{key}}` placeholders inside the partial. A missing
  parameter **fails the build** (typos can't reach production).
- Values may be `"double"` or `'single'`-quoted — use single quotes when the
  value itself contains HTML with double quotes.
- The directive can sit on its own line or inline inside markup
  (e.g. `<li><!-- @include components/cal-link.html label="Demo zdarma" --></li>`).

## Rules of thumb

- **Never edit `dist/`** — it is regenerated by `npm run build`.
- There is no watch mode — after editing `src/`, re-run `npm run build`
  (`npm run dev` does this automatically before starting `netlify dev`).
- Adding a new Cal.com or checkout button? **Use the existing components** —
  don't paste raw `<button data-cal-…>` markup.
- New landing section → new file in `sections/index/` + one `@include` line in
  `pages/index.html` (keep the page order obvious).
- Keep every file ≤ 500 lines; split when a file approaches the limit.
- CSS/JS stay inlined in the final HTML on purpose (zero render-blocking
  requests). Don't convert them to external files without re-measuring LCP.
